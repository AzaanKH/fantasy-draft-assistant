Prediction Layer Plan for the Fantasy Draft Assistant

Build a free-data prediction layer that learns from historical pre-draft ranks, player opportunity, team context, and actual season outcomes. Keep prediction separate from live roster-aware recommendation so the app can explain both "how good is this player?" and "is this the right pick for my roster now?"

Generated: May 28, 2026 Repo: fantasy-draft-assistant Target file: plans/first-pass.hmtl Primary strategy: free/open data + local cache

Executive Decision

Recommended first pass: use FantasyPros only for the current expert snapshot, Sleeper for live draft and market context, and nflverse/nflreadpy plus ffopportunity for historical training and backtesting. For historical pre-draft rankings, start with free DynastyProcess/ffverse ranking data through nflreadpy.load_ff_rankings(type="all") rather than trying to repeatedly call or scrape FantasyPros during model training.

What Changes

Add a new offline data pipeline and prediction artifact consumed by the existing player merge and recommendation engine.

  • data/predictions.json
  • data/model-features.json
  • scripts/src/build-prediction-dataset.ts
  • web-app/src/lib/calculations/prediction-score.ts

What Stays

The current app structure is good: React + shared types + cached JSON data + local Sleeper sync. The plan extends that shape.

  • FantasyPros snapshot adapter stays current-season focused.
  • Sleeper sync remains the live draft truth.
  • Team needs remain in recommendation logic.

What Not To Do

Do not train directly against the user's live roster need. That creates a model that learns roster construction artifacts instead of player quality.

  • No live API dependency during draft picks.
  • No unversioned scraping as the core training source.
  • No claimed edge until backtested.

Current App Fit

The repo already has the right separation points. The current recommendation engine in web-app/src/lib/calculations/recommendations.ts combines ECR, market rank, projected points, replacement value, tiers, survival probability, risk, and team need. The prediction layer should replace the heuristic projectedPoints, ceilingScore, floorScore, and injuryRiskScore proxies with trained or backtested values, then let the existing roster-aware recommendation scorer consume them.

Source Pulls Sleeper, FantasyPros, nflreadpy, ffopportunity, optional LeagueLogs
Normalize IDs Sleeper ID, FantasyPros ID, GSIS ID, ESPN ID, player name fallback
Feature Build pre-draft rank, ADP, age, role, team context, opportunity, historical form
Prediction points, VOR, ceiling, floor, uncertainty, breakout probability
Recommendation prediction + roster needs + scarcity + market value + survival

Storage Decision

Keep the draft app runtime on static JSON, and move historical modeling work into local analytical files. The recommended stack is JSON for browser consumption, Parquet for raw/intermediate extracts, and DuckDB for local joins, profiling, and model dataset creation.

Decision: use data/*.json as the runtime contract and data/model/fantasy-draft.duckdb plus data/model/*.parquet as the offline modeling workspace. Do not add Convex, Postgres, or Docker until the app needs multi-user hosted persistence or reproducible cloud training.

JSON Runtime

Best for the web app and extension because files are small, cacheable, easy to ship, and require no server during the draft.

  • data/fantasypros-snapshot.json
  • data/sleeper-adp.json
  • data/team-environment.json
  • data/predictions.json
  • data/model-report.json

DuckDB Modeling

DuckDB is an embedded analytical database: scripts open a local .duckdb file directly and run SQL against it. There is no database server to start.

  • Free and open-source under the MIT license.
  • Works well with Parquet and CSV files.
  • Good fit for player-season joins and backtests.
  • Not intended to be the live app state database.

When To Upgrade

Add a hosted database only when the product needs hosted multi-user workflows.

  • Use Convex if multiple users need shared live draft rooms or cloud sync.
  • Use Postgres if the app becomes a hosted SaaS with account data.
  • Use Docker if Python/nflreadpy setup becomes painful across machines.

DuckDB Usage Sketch

import duckdb

con = duckdb.connect("data/model/fantasy-draft.duckdb")

con.execute("""
  create or replace table weekly_player_stats as
  select *
  from read_parquet('data/model/raw/player_stats.parquet')
""")

con.execute("""
  create or replace table training_rows as
  select
    r.season,
    ids.sleeper_id,
    r.player_name,
    r.position,
    ranks.ecr_rank,
    stats.prior_year_points_per_game,
    opp.prior_year_expected_points_per_game,
    outcomes.actual_points
  from normalized_rosters r
  left join player_ids ids using (gsis_id)
  left join historical_rankings ranks using (season, player_id)
  left join prior_stats stats using (season, player_id)
  left join prior_opportunity opp using (season, player_id)
  left join season_outcomes outcomes using (season, player_id)
""")

con.sql("copy training_rows to 'data/model/training-dataset.parquet'")

Training Data Design

Create one player-season row per draft-relevant player. The model should see the player's pre-season information as it would have existed before draft day, then learn against the actual regular-season fantasy outcome.

Feature Families

Player Quality Features

  • Last 1-3 years fantasy points per game, weighted recent years higher.
  • Last 1-3 years expected fantasy points and opportunity share.
  • Position-specific efficiency: yards per route, yards per carry, TD rate, pass attempts, target share.
  • Age, years of experience, rookie indicator, missed games trend.
  • Contract-year and team-change indicators.

Market and Expert Features

  • Historical pre-draft overall rank and positional rank.
  • ADP or market rank where available.
  • Rank-vs-ADP delta.
  • Rank bucket, tier, and position scarcity at draft time.
  • Current-season FantasyPros snapshot only for the live draft artifact.

Team Context Features

  • Team points scored, plays per game, pass rate, rush rate.
  • Passing/rushing efficiency proxies from nflverse team stats.
  • Projected offensive environment from prior years and roster continuity.
  • Depth chart rank and role competition.

Outcome Labels

  • Full-season fantasy points in selected scoring format.
  • Fantasy points per game with minimum game thresholds.
  • Value over replacement by position.
  • Ceiling and floor from weekly distribution.
  • Top-N positional hit flags.

Rookies, Low-Experience Players, and Injuries

Missing NFL history must be modeled explicitly. A rookie with no NFL stats is not the same as a veteran with several low-production seasons. The dataset should preserve why data is missing and give the model cohort-specific features instead of converting missing history to zero.

Case Handling Feature Examples
Rookies Use a rookie-specific prior based on position, draft capital, age, team context, projected depth-chart path, current FantasyPros rank, and Sleeper ADP. isRookie, nflDraftRound, nflDraftPick, rookieRankBucket, depthChartPathScore
Year 2-3 players Use shrinkage: combine their limited NFL history with a position/age/draft-capital prior. Reduce the prior as the player accumulates real NFL usage. yearsExperience, gamesSampleSize, priorWeight, recentUsageTrend, roleChangeFlag
Veterans Use weighted 1-3 year production, opportunity, games played, efficiency, team changes, and role continuity. Recent seasons should usually carry more weight. weightedPointsPerGame, weightedXfpPerGame, missedGames3yr, teamChange, ageCurveBucket
Injured players Keep injury as availability and uncertainty, not just a raw quality downgrade. Adjust expected games, widen projection range, and add risk penalty when current status or missed-game history justifies it. currentNewsStatus, pupOrIrFlag, missedGames1yr, missedGames3yr, uncertaintyScore

Model Shape

The first pass does not need deep learning. Start with transparent, robust models that are easy to backtest, easy to ship as JSON, and easy to explain in the draft UI.

Baseline

Weighted heuristic using historical rank, prior-year points, opportunity, and team environment.

Why: fast to build, exposes feature bugs, and creates a benchmark.

Model V1

Gradient boosted trees or random forest trained per scoring format, with position as a feature or per-position models.

Why: handles nonlinear interactions like age curves and rank buckets without much manual tuning.

Ship Format

Offline script writes JSON predictions. Browser never trains the model and never depends on Python.

Why: keeps draft-day UX fast and reliable.

Recommendation Formula

Team needs belong after prediction. A player's baseline quality should not change because the roster needs a running back; the recommendation score should change because the roster needs a running back. 

recommendationScore =
  predictionValue
  + expertValue
  + marketValue
  + opportunityValue
  + scarcityUrgency
  + rosterNeedBoost
  + stackCorrelationBoost
  - uncertaintyPenalty
  - injuryRiskPenalty;
Component Source Example
predictionValue New prediction artifact Projected VOR and points, normalized by position.
expertValue FantasyPros current ECR Expert consensus rank and tier.
marketValue Sleeper ADP / optional LeagueLogs Positive when predicted value exceeds market cost.
scarcityUrgency Available-player pool + pick distance How costly it is to wait until the user's next pick.
rosterNeedBoost Existing calculateTeamNeeds Boost high-priority open starter slots; reduce late K/DEF until configured round.

League Draft History

The user's last four league drafts are highly valuable, but they should mostly improve recommendation timing rather than base player quality. Base prediction asks "how good is this player likely to be?" League history asks "will this player survive to my next pick in this specific room?"

Best Uses

  • Pick-survival probability by round, position, ADP bucket, and roster state.
  • League-specific positional runs, such as early QB/TE pressure.
  • Manager tendencies if draft slots/managers are stable across years.
  • Draft-room ADP correction: your league's actual cost versus Sleeper/FantasyPros market cost.

Do Not Use For

  • Training whether a player was good in the NFL.
  • Overfitting to one manager's unusual pick from a single year.
  • Replacing broad market ADP with a tiny league sample.
  • Changing the prediction model based on your current roster needs.

Implementation Phases

Data Audit

Goal: prove the free historical data can cover the last few draft years.

  • Install or script against nflreadpy.
  • Pull 2021-2025 historical rankings, player stats, rosters, schedules, teams, depth charts, and ffopportunity.
  • Profile missing IDs by year and position.
  • Write data/source-audit.json.

Dataset Builder

Goal: produce one reproducible player-season dataset.

  • Create scripts/src/build-prediction-dataset.ts.
  • Persist normalized player IDs.
  • Generate features and labels.
  • Add schema validation and row-count checks.

Backtest Baseline

Goal: measure whether this beats ECR-only decisions.

  • Train on seasons before the test year.
  • Simulate draft picks by historical available players.
  • Compare against ECR-only, Sleeper ADP-only, and current heuristic.
  • Report hit rate, VOR, regret, and calibration.

App Integration

Goal: make live recommendations consume prediction outputs.

  • Add prediction fields to shared Player type.
  • Merge data/predictions.json in usePlayerDataQuery.
  • Update recommendation diagnostics and UI explanations.
  • Keep cached fallback when predictions are missing.

Data Pull Sketch

The repository is TypeScript-first. For nflreadpy, the cleanest first pass is a small Python extraction script that writes normalized parquet or JSON, then TypeScript scripts consume those files. That avoids reimplementing nflverse download logic in Node. 

# scripts/python/export_nflverse_features.py
import nflreadpy as nfl

SEASONS = [2021, 2022, 2023, 2024, 2025]

player_stats = nfl.load_player_stats(SEASONS, stat_type="offense")
team_stats = nfl.load_team_stats(SEASONS, summary_level="week")
rosters = nfl.load_rosters(SEASONS)
depth_charts = nfl.load_depth_charts(SEASONS)
ff_ids = nfl.load_ff_playerids()
opportunity = nfl.load_ff_opportunity(SEASONS, stat_type="weekly")
rankings = nfl.load_ff_rankings(type="all")

# Write stable local extracts for TypeScript scripts.
player_stats.write_parquet("data/model/player_stats.parquet")

Backtesting

Backtesting decides whether the prediction layer is better than current rankings, not whether the model looks sophisticated. Run season-by-season walk-forward tests: train on all seasons before the target season and evaluate on the target season.

Metric Definition Why It Matters
MAE / RMSE Error between projected and actual fantasy points. Checks raw projection accuracy.
Top-N hit rate Percent of recommended players who finish top 12/24/36 at their position. Matches draft-useful decision quality.
VOR captured Total actual value over replacement from selected players. Penalizes empty points from replaceable positions.
Regret by pick Best available actual VOR minus selected actual VOR. Surfaces where the scorer misses obvious picks.
Calibration Do 70% confidence ranges contain the outcome about 70% of the time? Makes risk labels honest.
Pass condition for V1: the prediction-aware recommendation should beat ECR-only and the current heuristic on at least two of: VOR captured, regret by pick, and top-N hit rate. If it only improves RMSE, it is not necessarily better for drafting.

Keep the UI practical: users drafting live need direct recommendations and quick explanations, not a model dashboard.

Player Table Columns

  • Range: floor to ceiling marker.
  • Risk: low/medium/high from uncertainty and injury features.
  • Why: top two positive or negative drivers.

Known Risks

FantasyPros terms and competition risk: keep API use personal/non-commercial, cached, attributed, and current-season focused. Do not make FantasyPros API data the historical training backbone.
Risk Mitigation
Player ID mismatches across sources Use nflverse/ffverse player ID maps first, Sleeper ID as app key, and name/team/position fallback with duplicate detection.
Historical ranking coverage gaps Audit rankings by season, scoring format, and position before training. Exclude rows with missing pre-draft rank from rank-based tests.
Small sample size for season-level model Use simple models first, evaluate by position, and avoid overfitting with too many correlated features.
Draft-day source outage Every live source writes a cached JSON snapshot. The app reads local data during drafts.
False precision Display tiers, ranges, and top drivers instead of pretending point projections are exact.
