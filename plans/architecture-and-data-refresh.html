05 / Design Decisions

Why the system is shaped this way.

These are the durable boundaries that should survive implementation changes. Open any decision for the tradeoff it encodes.

Explicit refreshes, not hidden dev side effects

pnpm dev reports stale data but does not mutate tracked JSON or launch network-heavy refreshes. A normal coding session stays fast and reproducible, while draft preparation remains an intentional action.

JSON at runtime, DuckDB only for analysis

The web app and extension do not depend on a database server. DuckDB and Parquet are local modeling tools for joins, feature shaping, profiling, and backtests. Generated JSON is the small, inspectable runtime boundary.

Prediction and recommendation stay separate

Prediction answers "how good is this player likely to be?" Recommendation answers "how valuable is this player to my roster right now?" Roster need, scarcity, next-pick survival, and draft state belong in recommendation, not base player quality.

League history changes timing, not player quality

Imported personal Sleeper drafts estimate whether a profile is likely to survive until a later pick. That history should not teach the base model that a player is better merely because this specific room drafted the position aggressively.

FantasyPros is current context, not historical foundation

FantasyPros supplies current expert rankings, projections, and news. Open nflverse and ffverse sources are a better fit for historical feature engineering and backtesting. That keeps source responsibilities clear and reduces dependence on proprietary history.

Team environment is derived and intentionally conservative

The team environment refresh derives a completed-season baseline from nflverse TDs, yards, pass/rush volume, and EPA. Offseason news remains a separate signal. Coaching continuity is not sourced yet, so coachingStability defaults to false.

One canonical live snapshot

The local server polls Sleeper, normalizes picks through DraftSyncEngine, and streams SSE snapshots to both clients. This avoids separate client interpretations of the same live draft and keeps reconciliation logic in one place.

Cache current sources before the draft begins

TanStack Query treats player artifact loads as stable for the session. The draft UI does not repeatedly call current-source APIs while picks are happening. That keeps draft-day latency low and makes the viewed inputs auditable.

06 / Operating Recipes

Runbooks for the common cases.

Start commands from the repository root: fantasy-draft-assistant/.

Draft-week preparation

Use this when you want the full artifact set rebuilt before drafting.

pnpm prepare:draft
  1. Set FANTASYPROS_API_KEY in .env.local when API access is available.
  2. Run the command sequentially and let DuckDB finish its local writes.
  3. Review docs/draft-prep-report.md.
  4. Edit the keeper file when final keepers are announced, then regenerate the report.

Ordinary development

Use explicit refresh commands only when the stale report says the data needs attention.

pnpm dev
  • predev runs pnpm data:check and checks the dev ports.
  • The web app runs on http://localhost:3000.
  • The local sync server runs on http://localhost:3001.
  • Static player JSON is exposed to Vite through web-app/public/data.

Live Sleeper sync

The local server is the canonical live-state owner for both clients.

  1. Start pnpm dev.
  2. Open the web app and connect a Sleeper draft URL or ID.
  3. Load or reload the unpacked extension from extension/dist.
  4. Refresh the active Sleeper draft tab after reloading the extension.
  5. Verify the side panel and web app move with the same draft.
The server currently polls two Sleeper endpoints every 1000ms during live sync, or about 120 requests per minute for one local draft session.

Extension troubleshooting

The extension learns the current draftId from its Sleeper-page content script.

  1. Reload the extension in chrome://extensions.
  2. Refresh the actual Sleeper draft page.
  3. Close and reopen the side panel.
Chrome often does not reinject an updated content script into a tab that was already open. Refreshing the Sleeper page is required after an extension reload.
