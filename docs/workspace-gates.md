# Workspace gates

Run `pnpm verify` for type checking, lint, tests, and builds. Install the local demo fixtures with `pnpm data:demo:install` in a fresh checkout.

`eslint.config.js` owns lint policy. `vitest.config.js` owns test projects and the shared `restoreMocks`, `unstubGlobals`, and `unstubEnvs` policy. `gate-workspaces.js` records the package environments. Browser and extension globals, React hooks, and Node test relaxations remain separate config blocks.

`pnpm lint` checks generated documentation drift, tracked-tree leaks and tracked-data policy, then checks every package selected by `pnpm-workspace.yaml` for `lint`, `typecheck`, `test`, and `build` scripts. It also checks effective ESLint coverage and test discovery. Add a new workspace to `gate-workspaces.js` and supply all four scripts. Each lint command must execute `node ../scripts/lint.mjs <workspace>` directly or through `pnpm [exec] node` with the expected workspace. Echo stubs, shell combinations and mismatched workspaces fail.

Package commands still work, for example `pnpm --filter @fantasy-draft/cli lint` and `pnpm --filter extension test`. Each command checks only that workspace.

## Source and built package resolution

TypeScript, Vite, Vitest, and the package scripts that use tsx select `@fantasy-draft/source`. Consumers read the selected `shared/src/<subpath>/index.ts` even when `shared/dist` is absent or stale. For an ad hoc tsx command, pass `--conditions=@fantasy-draft/source`.

`pnpm test` runs ordinary suites without a build. The shared package contract tests deliberately use plain Node and the published declarations. `pnpm build` runs them after all builds through `pnpm test:contracts`. Run `pnpm test:contracts` directly only after building shared.

Server and scripts builds use separate TypeScript configs with the source condition disabled, so emitted Node imports still resolve the built shared package. Shared build forces emission to recover when dist was deleted but TypeScript's incremental metadata remains.

## Existing lint violations

`eslint-baseline.json` records occurrence fingerprints by source file and rule, with a reason for each entry. Fingerprints hash the diagnostic identity, its source range and enclosing declaration names from the TypeScript AST without line numbers; duplicates retain their multiplicity. `scripts/lint.mjs` checks each workspace with the root ESLint config, compares those occurrence multisets, and reports ordinary lint errors. The root command keeps pnpm's parallel workspace scheduling. The baseline covers existing JSON casts, cross-package imports including the CLI's web-app alias, and exported functions without boundary annotations. Tests keep their existing fixture relaxations and do not use these production baselines.

When you remove a violation, remove its occurrence from the baseline entry. Deleted and renamed files also require updates. A new occurrence in any file or rule fails, even if another occurrence disappears. Accepted occurrences remain hidden when another rule or file fails. If identical fingerprints exceed their allowance, every ambiguous occurrence stays visible. Agent-rule and blanket suppression comments require a written `-- reason`, even when ESLint suppresses the diagnostic. Fix the new violation. Decode external JSON with a shared decoder and import packages through public exports.

## HTTP requests

`http.json(url, decode, policy, options)` and `http.events(url, decode, policy, options)` require a decoder from unknown JSON to the caller's value. `http.text` and `http.bytes` handle non-JSON bodies. Every policy supplies `timeoutMs`, `retries` and `retryAfter`. The timeout covers headers and body per attempt. Events also require `idleMs` and `maxEventBytes`. The idle deadline pauses while the consumer processes a yielded event and resets when the consumer pulls again. Incomplete frames and comments do not reset it. Caller abort remains active during consumer processing. Their owner cancels the stream on consumer return.

The runner retries 429 and 503 by default when the explicit retry count permits it. The default backoff is 1,500 ms times the retry number. Retry-After accepts seconds and HTTP dates, keeps the existing 500 ms minimum, and stops rather than retrying early when the requested delay exceeds the default 10,000 ms limit. Retries add positive jitter below 10% of the delay, capped at 250 ms. Options allow injected fetch, time and randomness for tests. Caller abort cancels body reads and retry waits. `HttpError` distinguishes timeout, abort, network, status, invalid JSON and invalid stream failures, and strips credentials, query and fragment from its URL.
