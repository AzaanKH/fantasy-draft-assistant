# Unit 11 persistence waves

Unit 11a changes tests and tooling only. The browser adapter drives the existing default store and its CAS, lineage, and unconfirmed-save code. Its first two-tab smoke case acknowledged 600 effects and retained 358 after reload, with 242 absent from both stores. Concurrent acceptance does not establish durability. The reproducible defects are in [the defect record](unit-11-defects.md). Final measured totals are included there. The stress loss rate describes this artificial contention schedule, not a predicted frequency for users.

The target is Amendment 1's B1 IndexedDB transaction design. Web Locks around localStorage are ruled out by unit 0. The cleanup must follow a proven replacement, rather than erase the compatibility reader before migration.

## 11b: one workspace command path

Keep the existing persistence medium and stored v1 shape. Create a workspace instance at the browser composition root, inject the draft and connection stores, and provide `useWorkspace().send`. Route all UI commands, sync reconciliation, mock CPU commands, and connection changes through that instance. Keep `useDraftView(selector)` as the read path. Add a separate `useNow` subscription for age and timer display. The clock must not trigger the recommendation board or the command owner.

- `web-app/src/App.tsx`, `main.tsx`, the draft-room composition root, `LiveDraftSyncProvider.tsx`, and the side-panel composition root.
- `web-app/src/hooks/useDraftSync.ts`, `useDraftSyncReconciliation.ts`, mock auto-advance, player-action, shortlist, and provisional-pick callers.
- Existing store, workspace, hook, and draft-flow tests, plus `scripts/persistence/adapter.mjs`.

Enumerate callers with `rg 'useDraftStore\.|useDraftSyncConnectionStore\.|useDraftStoreApi|createDraftStore' web-app/src` before the cut. Expect fewer than 80 changed files. If the actual inventory reaches 100 files, split caller migration from singleton deletion, keep the old API until the next independently green PR, and report the split to the stack root. Do not leave two writable owners in one shipped state.

Tests cover isolated workspaces, provider binding before reconciliation, a fresh imperative view, clock-only renders, all command families, accepted and rejected provisional picks, and the unchanged persistence suite. Run `pnpm verify` and the same four browser scenarios. For the two shared-origin scenarios, require each 600-command sequential control to retain 600 of 600. For missing permission and split-hostname controls, preserve the characterized partition split: each side retains its own 300, the union retains 600, and both do not claim one common session. Extend conflict cases to 20 samples. A positive conflict sample must retain at least one acknowledged pick without duplicate slots or players. One or two acceptances remain a known legacy race; do not require the same racy winner or reproduce double acceptance as desirable behavior. Queue permutations and exact settled order must agree in shared storage. For concurrent shared-origin stress, compare three suites of five seeds against 11a: aggregate loss must stay within 5 percentage points, and no run may exceed 11a's worst per-run loss by more than 30 of 600 effects. These are non-regression bands for this stress schedule, not a durability gate. Any new failure class or out-of-band result requires investigation and blocks 11b until explained or fixed. 11b need not fix the pre-existing algorithm. The harness must still call the app's live owner, with no old singleton imports. No persisted byte or key change belongs here, so deployed main tabs continue to use the same v1 data. Run the existing old-reader round-trip gates from unit 10b-1.

## 11c: transactional persistence and explicit handoff fence

Build a readwrite IndexedDB transaction per command. Read the latest facts, validate and apply the command, write the new facts, and acknowledge only after transaction completion. Do not acknowledge on request success or before `transaction.oncomplete`. BroadcastChannel notifications are hints. Focus and visible-state visibility changes re-read the database after missed hints. Surface abort, quota, blocked-open, upgrade, and storage-access failures without claiming a durable save.

Start from these files:

- New browser persistence and import modules in `web-app/src/workspace/`, with the owner, provider, and command types from 11b.
- Existing `draftSessionStorage.ts`, `draftSessionUnconfirmedSaves.ts`, and `draft/saved-session.ts` as retained import-only dependencies.
- `shared/src/catalog/sync-decoders.ts` and the stored-session boundary decoders it references.
- `shared/src/local-dev.ts`, `extension/src/shared/local-urls.ts`, `extension/src/shared/types.ts`, `extension/src/sidepanel/sidepanel.ts`, the side-panel HTML, and extension URL and permission tests.
- Workspace, migration, lifecycle, permission, rollback, and persistence tests, plus the browser adapter and runner.

Choose one canonical origin for the local app and extension, `http://localhost:<configured web port>`. Reject or navigate a conflicting loopback hostname before a writable workspace mounts. Do not claim a redirect migrates a different origin's storage. The old origin must export its own records before handoff. At side-panel start, verify the configured origin and host permission, then use a nonce written and read by a cooperating top-level window to prove that the frame shares the same storage partition. Do not let the frame write before this check. If no app tab is open, create a temporary top-level canonical-origin storage-check page that never mounts a workspace writer. Commit a nonce in a separate IndexedDB probe store, prove a round trip between the helper and frame, then remove the probe and close only that helper. This checks the chosen persistence medium, not just localStorage availability. If opening the helper is blocked, the existing Open web app action starts the same handshake. The panel stays write-blocked while that action is pending. Test startup with no existing tab as a supported path. A failed, unavailable, or timed-out check uses the existing permission or setup error flow. An IndexedDB API being available is insufficient.

Decode independent pick, queue, and keeper entries separately within each session. Keep valid entries and retain rejected raw entries with diagnostics. Preserve a dependent move or cursor group atomically when its members cannot be interpreted separately; name and test that dependency rather than silently dropping the whole session. Import each v1 session independently, including optional `draftProgress.anchor` and `historyLength`. Preserve insertion-order history and the pick-order meaning of `historyLength`; do not sort one without translating the other. Import unconfirmed journals independently, and resolve valid dependencies before considering a session imported. Keep unresolved valid journals and report them instead of deleting them. Invalid independent entries produce a diagnostic while valid entries survive. Dependent pick moves remain atomic. Preserve original bytes for every rejected record and report failures once per offending value. A storage exception is an error, never an empty successful import. Put Effect decoding at the storage boundary, and keep pure store tests off the full catalog barrel.

Use a new database and migration metadata key that old readers ignore. Retain v1 records and journals unchanged until migration commits. Record import completion inside the same transaction as imported facts. A crash or blocked transaction can be retried without duplicate picks. Estimated scope is below 65 files. If migration and extension integration do not fit, split 11c into an import-reader PR and an activation PR. Both keep the fence closed until the activation gates pass.

### Amendment 7: no simultaneous old and new writers

Choose an explicit handoff fence, not asynchronous write-through mirroring. The characterization shows that the current localStorage writers can acknowledge changes that a concurrent stale write erases. A new mirror would still race that writer, and an old reader cannot see IndexedDB facts after rollback. Import-on-newer alone has the same rollback gap.

The supported mixed-version state has a main-version tab writing v1 and a new-version tab open in a read-only compatibility screen. The new tab imports a raw snapshot for inspection but sends no draft command and does not change the v1 head or journals. The importer is pure over copied bytes. It must not create a v1 store: that reader deletes journals and can rewrite the head during recovery. It offers a handoff that closes every old draft tab and extension panel before activation. Take the final v1 snapshot only after all old execution contexts have stopped, and preserve the raw export before the IndexedDB import commits. Abort the handoff if an old writer is still running or if the captured source changes. Unresolved journals keep activation blocked. Then reopen only new-version writers.

A new localStorage marker, a new Web Lock, elapsed quiet time, an old tab's failure to respond, or a checkbox cannot fence JavaScript that is already loaded from main. Old modules do not honor those signals. Make 11c's first activation experiment a managed-browser maintenance handoff. A local host owns the browser profile, pauses new page and frame execution before application scripts run, enumerates every existing application frame and worker, closes the old application contexts, exports the final v1 bytes, and launches only an attested new build. The host retains that execution guard while IndexedDB writes are active. On loss of the host guard, writers stop and activation becomes unavailable. This is a proposed mechanism with a falsifiable gate, not a claim that the current tooling already implements it.

The installed extension is a narrower candidate for the single-profile inventory: [Chrome's tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs) can query and remove matching tabs, and [the side-panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) can close its own panels. Closing matching top-level tabs alone does not establish that every frame and worker stopped. The activation experiment must include nested frames, restored cached tabs, worker contexts, a second browser profile, an incognito context, a non-extension browser, and a user without the extension. It must either stop every context that can write the migrating storage partition before script execution resumes, or explicitly refuse activation there. Other profiles have separate browser storage and need separate imports and handoffs; the bridge cannot claim it fenced them through one profile's tab list. Without a complete, enforceable inventory, the app remains on the read-only compatibility screen and the operator must perform a browser-profile shutdown and managed restart. A confirmation checkbox alone never grants activation.

The pass test opens real old-module writers in those contexts, attempts picks at each handoff boundary, restores an old cached page after activation, and terminates the host guard mid-command. Zero legacy acknowledgements may occur after the fence closes, and every acknowledgement before closure must be in the imported or retained raw data. Every unowned profile must refuse its own activation. A missing pause, a surviving old context, an untracked worker, an unknown profile, or inability to stop restored code is an explicit failure. Ship the importer and read-only screen with IndexedDB writes disabled if the experiment fails. The activation PR is not authorized to replace this test with a best-effort tab reload.

Before activation, the default deployment can continue using 11b's v1 writer, with D1, D3, and D6 explicitly unfixed. The read-only compatibility screen is the migration attempt, not a claim that a closed fence has already replaced normal persistence. If a handoff fails before any new IndexedDB acknowledgement, return to 11b only after proving that the raw v1 snapshot remains unchanged and that no new acknowledged facts exist solely in IndexedDB. Once new IndexedDB commands have been acknowledged, loss of the guard leaves the new view read-only with those facts retained. It cannot silently fall back to a v1 writer. Unit 11d remains blocked until activation and reverse-handoff gates pass. The stack root owns the decision to extend the guard experiment, use a controlled maintenance rollout, or defer activation. A green importer PR alone does not complete unit 11c.

Rollback follows the reverse handoff. Stop all new writers, export every committed fact to a v1-compatible record and recoverable journal shape, verify those exact bytes with real `origin/main` readers and writers, then open old writers. Keep the database and raw export for recovery. An old cached page that returns after activation must be stopped by the same host-controlled fence before it can acknowledge a command. If that cannot be guaranteed, an online rollback is unsupported and the activation gate stays closed. Never clear storage to resolve a disagreement.

The read-only gate first snapshots the exact values and key set of every v1 session and unconfirmed-journal key. Open, focus, re-read, and close the new compatibility view. Assert byte-identical values and the same keys. Repeat between serialized commands from a real `origin/main` writer and compare each boundary to that writer's own after-write snapshot, so legitimate old writes are not mistaken for importer writes. Run a proxy that rejects new-view storage mutations as a second check.

The old-module gate loads real modules from pinned `origin/main` and 11b in isolated browser realms. It does not reimplement their decoder. Drive picks, corrections, removals, queue edits, keepers, progress anchors, and journal recovery through old writes and new read-only inspection. At the enforced handoff, stop the old realm, activate new writes, reload, export for rollback, then run the real old writer against that export. Compare pick identities, cursor, keepers, queue, and manual-continuity facts at every boundary. Retain modules and exact SHAs as fixtures. Inject interruptions before and after import completion and rollback export. Reject a rollout design that demonstrates only new-reader success.

### Activation gates

Run `pnpm verify`, v1 per-entry corruption and journal dependency tests, storage failure and transaction-abort tests, origin and permission tests, and the complete old-module handoff and rollback gate. Convert 11a's expected failures to passing tests when fixed. Retain tests that prove read-only coexistence produces zero new acknowledgements and zero mutations to old keys. Instrument IndexedDB transaction aborts and errors in the adapter; the current localStorage instrumentation cannot detect them.

The real-app browser gate must retain all 9,000 acknowledged effects in the two-tab case and all 9,000 in the installed extension case with host permission. Rejections in the disjoint workload are failures. Negative origin and permission cases must block every attempted write and show the existing setup error. In 11c, rewrite the runner and `failsGate` negative branch to model a blocked workspace explicitly: attempted commands are counted, all acknowledgements are zero, rejection is expected, and old session keys remain unchanged. The current 11a negative branch deliberately fails on any accepted write and its generic rejection check is not the future blocked-state gate. Do not count a frame timeout as successful blocking. Check conflicting picks with exactly one durable acceptance and an explicit losing result, plus exact queue order after reload. Close a writer after transaction commit and before notification; trusted focus must recover from both directions. Exercise a native hidden-to-visible transition or report that native visibility remains unproven and keep that activation gate open. Assert that both lifecycle callbacks are registered and dispose on workspace teardown.

## 11d: remove obsolete persistence writers

After 11c clears activation and rollout gates, delete the CAS retry loop, lineage merge writer, unconfirmed-save writer, and their store subscriptions. Delete old singleton compatibility APIs left only for tests. Retain a small, read-only v1 importer and the real old-module fixtures needed by the rollback contract. Cleanup does not authorize deleting data or the importer. Remove fields and exports only after a caller search finds no supported reader.

Start from `web-app/src/stores/draftStore.ts`, `draftSessionStorage.ts`, `draftSessionUnconfirmedSaves.ts`, `draft/saved-session.ts`, their test files, and the import owner in `workspace/`. Update shared stored-session or journal exports only where there is no remaining import or rollback reader. Expect fewer than 30 changed files.

Run `pnpm verify`, the full 11c browser and old-module gates, and searches proving that no workspace command writes v1 directly. The explicit handoff and rollback rules remain in force. Do not delete the compatibility fence merely because the new writer no longer imports the old store.

## Evidence and delivery rules

Each PR stays below 100 changed files, remains independently green, records three sequential verification wall times, and receives independent review. Keep browser stress separate from `pnpm verify`. Record trunk defects separately from regressions caused by a wave. The stack root owns all rebases and PR retargets. No wave runs live provider refreshes.
